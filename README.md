# 📮 Omi 的邮票识别大师 / Omi's Stamp Master

一个 **OpenClaw Skill**——基于 **OCR + CLIP 图像检索 + 视觉大模型精读** 的中国邮票本地识别工具（1949-2025 全覆盖）。
识别输出志号、名称、发行日期、面值明细、齿孔、尺寸、版别、印刷厂、发行量等完整收藏信息，并附带目录参考图供人工核对。

> 本仓库既是可安装的 OpenClaw Skill（[SKILL.md](SKILL.md)），也可作为独立的 Python 工具使用。
>
> ⚠️ **数据源需自行下载**：识别依赖本地《中国邮票电子目录》目录库（2,003 套票），
> 该数据**不随本仓库分发**，需自行获取 CHM 数据源并构建（获取与构建方法见
> [docs/BUILDING.md](docs/BUILDING.md)）。未构建目录库前，识别无法工作。
>
> 识别链路**离线优先、零云成本路径默认开启**。

## 功能特性

- **能够多枚识别**：整版 / 方连 / 多枚同框照片自动拆分，逐枚识别（最多 12 枚）（但还是建议单枚识别）
- **信销票友好**：邮戳覆盖不影响识别（CLIP 抗干扰 + OCR 文字过滤）
- **三级证据链**：
  1. OCR 票面文字检索（印刷体直接命中，如「贺龙同志诞生九十周年」→ J126）
  2. CLIP 图像匹配（无字票 / 书法字票的兜底）
  3. 视觉大模型精读（OCR/CLIP 都没把握时才触发，可配置关闭）
- **完整收藏信息**：齿孔、尺寸、版别、印刷厂、发行量、单枚面值明细
- **目录参考图**：识别结果附带目录原票扫描图，人工看图秒判
- **成本透明**：每次识别输出 `vision_calls` 字段（本次调用视觉模型的次数），
  缓存命中不计费，纯本地 OCR+CLIP 场景零云成本
- **离线优先**：本地全链路（OCR + CLIP + 目录检索），照片不出机器；
  视觉大模型仅作为可选的最后兜底

## 技术栈

| 模块 | 技术 | 说明 |
|---|---|---|
| 图像预处理 | OpenCV | 邮票区域检测（Canny）、裁剪、透视矫正、多枚拆图 |
| OCR | RapidOCR（onnxruntime） | 模型随 pip 包自带，CPU 快，免下载 |
| 图像匹配 | CLIP（openai/clip-vit-base-patch32） | 对本地目录库图片索引做相似度检索（HF 离线模式） |
| 视觉精读 | 通义千问 VL（qwen-vl-max） | 仅 OCR/CLIP 无把握时触发；无 API Key 自动降级纯本地 |
| 目录库 | 本地《中国邮票电子目录》解析 | 2,003 套票元数据 + 8,946 张唯一图片索引 |

## 快速开始

### 作为 OpenClaw Skill 安装

将本仓库 clone 到 OpenClaw 的 skills 目录即可被识别加载：

```bash
# OpenClaw 技能目录（路径随安装方式而异）
cp -r omi-stamp-master /path/to/openclaw/skills/omi-stamp-master
```

然后在对话中发送邮票照片，或说“识别这张邮票”即可触发。
Skill 的触发方式、输出格式与使用约定见 **[SKILL.md](SKILL.md)**。

### 依赖安装

```bash
pip install -r requirements.txt
# torch 2.x+cpu 需单独安装（CLIP 推理用）
pip install torch --index-url https://download.pytorch.org/whl/cpu
```

### 构建目录库（必需）

识别依赖本地目录库（`catalog/catalog.json` 元数据 + `catalog/index.npy` 图片索引）。
目录库由《中国邮票电子目录》CHM 数据源解析而来，**不随本仓库分发**，需自行获取后构建。

**一键构建**（自动探测 + 解析 + 建索引）：

```bash
python tools/setup.py <CHM解压根目录>
```

完整流程、数据获取方式、分步构建与排错见 **[docs/BUILDING.md](docs/BUILDING.md)**。

### 识别一张邮票

```bash
python tools/recognize.py <图片路径> --catalog catalog [--json] [--no-vision]
```

- `--json`：输出结构化 JSON（识别结果 + 参考图路径 + `vision_calls` 成本标记）
- `--no-vision`：禁用视觉精读，只走本地 OCR+CLIP（零云成本）
- 默认输出 Markdown 报告（完整字段 + Top 候选）

### 视觉精读（可选，需 API Key）

视觉精读读取 API Key 顺序：环境变量 → 项目根 `.env` 文件。
两者都未配置时自动降级为纯本地流程，不报错。

```bash
# .env
DASHSCOPE_API_KEY=your-key-here
```

## 平台支持

- **Windows / Linux / macOS** 均可运行（Python 3.9+）
- 中文路径图片读取：优先 `cv2.imread`，Windows 中文路径自动退回 `np.fromfile` 方案
- 控制台输出统一 UTF-8（避免 Windows GBK 控制台 emoji 报错）
- 目录库构建脚本兼容 CHM 源的 GBK 编码 HTML

## 数据获取说明

本项目的目录库来自集邮爱好者社区整理的公开电子目录《中国邮票电子目录》
（CHM 格式，覆盖 1949 年至今全部纪特票、普票、个性化票等，共 2,003 套）。

**构建步骤**：

1. 通过搜索引擎检索「中国邮票电子目录 CHM」获取数据源（该目录在集邮社区
   有公开传播版本，请自行确认所获取渠道的合规性）
2. 解压 CHM（可用 7-Zip / chmlib 等工具）得到 HTML 数据目录
3. 按上文「构建目录库」执行解析与建索引脚本

## 识别链路设计

```
输入图片
  └─ 拆图（Canny 轮廓 / OCR 文字框定位 / 竖排扩展 / IoU 去重）
       └─ OCR 票面文字
            ├─ 高置信 → 文字检索目录 → 直接出结果（零云成本）
            └─ 低置信 → CLIP 图像匹配
                 ├─ 高置信 → 出结果
                 └─ 低置信/扎堆 → 视觉大模型精读（志号/年份/面值/图案）
                      └─ 多证据融合：志号(+100) > 年份/面值/生肖 > OCR > CLIP
```

## 使用建议：单枚识别优先

**推荐单枚拍摄识别**——识别精度和速度都最优：

- ✅ 单枚票：拆图直接命中，OCR 文字/CLIP 匹配完整，通常 2-6 秒出结果
- ✅ 单枚票特写：完整性判定为 full，输出全部收藏字段 + 参考图
- 📷 拍摄建议：票面拍正、光线均匀、尽量避开邮戳遮挡关键文字

**多枚识别（整版/方连/册页）支持，但有以下已知问题**：

| 场景 | 遇到的问题 | 结果表现 |
|---|---|---|
| 密集册页（3 行 12+ 枚） | 轮廓检测只拆出 1-2 枚（大框吞票/掩膜残留） | 部分票识别不到，识别到的区域标 partial |
| 多枚同框紧贴 | 相邻票文字互相混入拆图区域 | 志号/文字检索可能串票，需人工核对 |
| 护邮袋/背景复杂 | 袋边/页面轮廓被误当成邮票 | 区域过大判 partial，不读全字段 |
| 竖排文字票 | 文字带被切成长条，票面主体框不住 | 依赖 OCR 文字定位兜底，可能只出候选 |

> **根治办法**：多枚场景请逐枚拍摄（或逐枚裁剪后再识别），识别结果会诚实标注
> partial（不完整区域只给候选、不给全字段），不会硬报错误答案。

## 已知边界

- **密集册页拆图**：3 行 12+ 枚的册页照片，轮廓检测只能拆出 1-2 枚，
  根治需单枚拍摄（识别结果会诚实标注 partial）
- **黑白低对比度票**（如 J122 邹韬奋）：OCR 无字 + 视觉模型也难读，
  链路会诚实降级为 uncertain，需单枚高清图/扫描件
- **CLIP 区分度**："个"字头红底大字个性化票分数扎堆（0.72-0.80），
  排名不可靠，靠视觉精读志号 + 人工看图确认
- **OCR 读不出书法/艺术字**（如"五福临门"的福字），但印刷体文字可靠
